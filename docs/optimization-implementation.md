# 优化实施与验证

实施日期：2026-10-08。沿用 Tauri 2 + Rust + 原生 JavaScript，按 [优化评估](optimization-review.md) 渐进调整，无需更换技术栈。

## 已实施的改动

| 范围 | 结果 |
| --- | --- |
| 保存与应用 | 新增 `download_online_wallpaper` 命令，保存仅下载；应用才设置桌面。随机候选失败后继续尝试，最多三个候选 |
| 配置与历史 | Rust 模型保留随机图源、主题、自定义颜色、AMOLED；旧配置补默认值，主题 localStorage 一次性迁移；历史补作者及版权链接，旧记录兼容 |
| 自动轮换 | Rust 后台单个任务执行轮换，窗口隐藏后继续运行；更新配置会重设计时，关闭开关停止后续轮换；单次错误会报告并继续下一轮 |
| 在线请求 | 图源、查询、页码使用请求快照，只有最新请求可更新界面；相同请求合并，失败分页回退；图片预览仅允许一次备用加载 |
| 删除反馈 | 批量命令逐文件返回成功和失败，失败图片保留选择状态；文件操作限定在当前壁纸目录，避免误删其他文件或无关 JSON |
| 图片加载 | 独立 `images.js` 提供可见区域加载、最多四个前端请求并发；Rust 后台生成最长边 480px 的 JPEG 缩略图，按源文件路径、大小及修改时间复用缓存 |
| 本地资源 | 卡片使用 Tauri asset 协议，授权后才提供文件地址；仅打开大图时读取原图，本地列表不再通过 IPC 传输整图 Base64 |
| 长列表 | 独立 `virtual-grid.js` 对超过 120 张的统一比例图库及在线列表挂载可见行和缓冲行，释放离屏图片；元数据仍保留以便反向滚动恢复 |
| 页面启动 | 首次只加载配置和本地图库；发现页、历史页进入时加载；目录扫描、缩略图生成和持久化放到后台任务 |
| 下载服务 | 复用 HTTP Client，API 与图片使用不同超时；流式写临时 `.part` 文件，限制体积和解码尺寸，检查 HTTP 状态、图片内容与真实格式后提交；文件名净化并加入 URL 哈希 |
| 图源边界 | Bing、Unsplash、Wallhaven、Pexels API 独立到 `providers.rs`；网络和响应格式错误正常返回。Pexels 有 Key 时使用 API 并报告失败，无 Key 时使用有限的内置目录，目录耗尽正常结束 |
| 持久化 | 配置、历史迁至应用数据目录；兼容复制旧 `config` 数据，保留原文件；同目录临时写入与替换，保存上一份有效备份，损坏时保留坏文件并尝试恢复 |
| 并发与实例 | 历史统一协调写入，配置保存前后端均排队，下载在单实例内串行协调；真实单实例插件使重复启动恢复已有窗口 |
| 桌面与资源边界 | 浏览器链接改用 Windows 原生打开，后端限定 HTTP(S)；启用 CSP，asset 协议按验证后的具体文件授权；缩略图超过缓存数量阈值时清理旧项 |
| 维护与交付 | 新增版本/IPC 命令校验、PR 和发布前检查，测试目录取消忽略；锁定 Tauri CLI，更新测试依赖；补 MIT 文件，四种语言 README 更新启动方式、配置示例及数据位置；常用动态提示纳入 i18n，去除远程 Google Fonts CSS 依赖 |

后端新增 `gallery`、`storage`、`network`、`providers`、`thumbnails`、`rotation` 模块，保留薄命令层和现有界面操作方式。

## 验证结果

- `npm run test:all`：版本和 27 个 IPC 命令校验通过，52 项样式校验通过，17 个文件中的 305 个前端测试通过。
- `cargo test --locked`：18 项通过，2 项依赖真实 Bing/GitHub 服务的测试默认忽略。存储、下载、历史测试使用临时目录；网络下载集成测试使用本机 HTTP 服务。
- `cargo clippy --all-targets --locked -- -D warnings` 与 `cargo fmt --all -- --check`：通过。
- `npm audit`：未发现已知漏洞。
- Windows 调试程序编译、启动成功，主窗口标题为 Wallpaper、进程响应正常。
- 真实 WebView2 冒烟检查：配置、图库、历史 IPC 与事件权限通过；当前目录中 5 张图片能扫描，缩略图通过 asset 协议解码成功；新模块已加载，检查期间没有 JavaScript/CSP 错误。
- 真实单实例检查：再次启动可执行文件后，第二个进程正常退出，已有实例保持运行。

### 本地页隐藏后图片恢复

随机下载完成时，本地图库会在后台刷新。WebView2 对隐藏页面中的图片有时不会在页面重新显示后再次触发可见区域观察，表现为卡片存在但图片地址为空。现在切回本地页会主动唤醒已挂载卡片的图片任务；缩略图生成或缓存异常时还会回退加载原图一次。真实 WebView 验证当前 7 张图片全部解码成功、0 张裂图，并补充了隐藏页面恢复和原图回退测试。

### 可复现的结构基准

运行 `npm run benchmark`，在 JSDOM 中模拟 800px 宽、600px 高、三列的统一比例网格：

| 图片数量 | 首次挂载卡片 | 缩略图 IPC 请求 | 完整原图 Base64 IPC 请求 |
| --- | --- | --- | --- |
| 100 | 100 | 100 | 0 |
| 500 | 33 | 33 | 0 |
| 1000 | 33 | 33 | 0 |

JSDOM 没有真实布局、图片解码和 WebView 内存行为，这些数字只验证挂载和 IPC 数量控制。真实浏览器还会根据 IntersectionObserver 可见范围减少缩略图请求。不据此宣称启动加速百分比、内存降幅或滚动帧率。

## 运行测试版

在项目目录执行（已安装依赖时直接运行第二条）：

```powershell
npm ci
npm run dev
```

关闭窗口会隐藏到托盘，托盘“退出”结束程序。开发进程也可用终端 Ctrl+C 结束。构建安装版使用 `npm run build`。

配置和历史位置为 `%LOCALAPPDATA%\com.wallpaperapp.dev\settings.json`、`history.json`。图片仍存放在设置中选择的壁纸目录；默认是用户文档下的 `wallpaper_app`。迁移旧数据时复制，不删除原配置和原图片。

高级检查可在启动开发版前为 WebView2 设置本地调试端口，再运行 `node scripts/smoke-webview.mjs`。脚本默认读取 `http://[::1]:9222`，也可传入实际本机端点参数。它只读应用状态及图片，不调用桌面设置或删除操作。日常运行无需开启调试端口。

## 后续可继续完善的范围

- 原始图片比例的行高不固定，目前使用常规网格和图片懒加载；虚拟化只覆盖统一比例模式。
- 尚未测量真实 WebView 的启动时延、Rust/WebView 内存峰值和快速滚动帧率；应在真实 100/500/1000 张样本及统一机器上补充测量。
- 自动轮换时序有测试，完整的真实桌面切换、托盘长时间运行、安装包升级和重启后的交互仍需桌面验收；本次测试没有修改用户桌面壁纸。
- 前端已拆出图片与虚拟网格，剩余 `app.js` 的配置、主题、弹窗等可继续渐进拆分；TypeScript/JSDoc 及全部样式/文案整理可另行推进。
- CI 工作流已加入源码，本次验证在本机完成；远程 Actions 需提交后运行。
